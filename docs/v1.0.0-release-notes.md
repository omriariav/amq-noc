# amq-noc v1.0.0

amq-noc 1.0 is the command center for amq-squad 3.0 squads. It replaces the
0.x board completely.

```sh
go install github.com/omriariav/amq-noc/cmd/amq-noc@v1.0.0
```

Requires `amq-squad` 3.0 or newer and `amq` on `PATH`. If you still run
amq-squad 2.x, stay on `amq-noc@v0.13.0`.

## What it is

- One screen: every seat and task, grouped by project path, four bucket tabs
  with counts (Needs you, Working, Ready, Inactive), a details pane and
  keyboard navigation.
- One input: `amq-squad status --json` (schema 1), read every 5 seconds.
  `--root DIR` passes the squad's root through (`status --root DIR --json`);
  `--fleet` reads every squad (`status --fleet --json`). Without either,
  amq-squad uses `AM_ROOT`; outside a squad's shell amq-noc says how to point
  it at one. An empty fleet shows an empty board.
  amq-noc never reads `.amq-squad/` files and never computes a bucket.
- Three controls:
  - `n` runs the status contract's `new_task` argv with the values you fill in.
  - `enter` opens the AMQ conversation with the squad's lead (`amq thread`,
    `amq send`, with a staged confirm).
  - The details pane shows gates and attention items. Answering a gate is not
    done here.
- It starts only a bare `amq-squad` or `amq`, as an argv array, never a shell.

## Shown from the status contract

- Unknown bucket values show as Inactive (unknown), with a warning line, so
  one bad row never blanks the screen.
- A seat the contract marks `live: false` outside Inactive gets a ⊘ marker.
- Fleet mode: the operator's own row as an Operator group, and squads held
  back by the fleet cap as a Waiting group.
- Attention items: each row lists its own items (kind, severity, subject), and
  every row of a squad shows the squad-level items. amq-squad 3.0.1's launch
  failures (`seat_launch_failed`, with stage, reason and detail) show here.

## Removed

The whole 0.x surface is gone: the `noc` subcommand and its flags (`--root`,
`--filter`, `--json`, `--refresh`, `--action`, `--run-action`, `--notify` and
the rest), team launch and stop/resume/restart, pane and runtime controls,
`doctor`, `preflight`, threads, workstream, briefs seed, and the built-in
classifier and attention queue. `amq-noc --help` and `amq-noc version
[--json]` remain.

Where each removed job lives in amq-squad 3.0 is tabled in
`docs/v1-command-center-execution.md` ("Removed verbs and where each job lives
in 3.0"). In short: `amq-squad lead --team` for launch, `amq-squad doctor` for
doctor, and `amq-squad status --json` for snapshots.

## Build

go.mod drops `bubbles` and `fsnotify`. No module-path change: v1 keeps
`github.com/omriariav/amq-noc`.
